## 2026-06-10 - Secure Logger Implementation for PII Leakage
**Vulnerability:** UI components and screens were using raw `console.log` and `console.error` alongside `alert()` concatenations which risked dumping full entity objects containing PII into production logs or directly to users.
**Learning:** PII leakage often happens via generic error logging (e.g., `catch(e) { console.error("Error", e) }`) where the full error object or context entity is logged, or directly rendered in UI dialogs.
**Prevention:** Use a centralized secure `logger.ts` utility that suppresses non-error logs in production (`import.meta.env.MODE`) and actively strips complex error objects (falling back to `error.message` or `String(error)`) to prevent unintended exposure of raw entity data. Never concatenate dynamic errors to user-facing strings (e.g. `alert()`).
