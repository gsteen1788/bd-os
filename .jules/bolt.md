## 2024-03-20 - O(1) group lookup over O(N*M) loop filtering
**Learning:** Calling `.filter()` on an entire collection (like `opportunities` or `protemoi`) inside a render loop over a finite set of categories (like `stages`) introduces an $O(S \times E)$ performance bottleneck. This pattern causes unnecessary repeated array iterations when $E$ (entities count) grows, delaying main-thread rendering.
**Action:** When a screen needs to display items grouped by a category property (e.g. kanban columns or board stages), proactively use `useMemo` to group the entities into a `Map` in a single $O(E)$ pass. Inside the render map over the categories, use `$map.get(category) || []` for an $O(1)$ constant-time lookup.
## 2024-03-22 - Anti-pattern: Memoizing infrequent onClick array searches into the render loop
**Learning:** Extracting an \(O(N)\) array search (`array.find()`) that originally executed only during an infrequent `onClick` callback into a `useMemo`-generated `Set` causes the computation and memory allocation to happen on *every render* when dependencies change. This degrades performance instead of improving it.
**Action:** When identifying loop optimizations, distinguish between computations that happen synchronously during the render cycle (e.g. filtering a list to display) versus computations that happen asynchronously in event handlers (e.g. `onClick`). Only memoize render-blocking operations. Let event handlers perform their localized \(O(N)\) lookups.
## 2024-03-23 - Anti-pattern: Unmemoized intermediate array filters breaking downstream useMemo caches
**Learning:** If you filter an array during a React render cycle (e.g., `const filtered = items.filter(...)`) and then pass that `filtered` array as a dependency to a downstream `useMemo` hook, the `useMemo` cache will be busted on *every single render*. This happens because `filter` returns a new array reference each time, silently destroying intended performance optimizations (like O(N) grouping operations).
**Action:** Always wrap intermediate array transformations (like `.filter` or `.map`) in their own `useMemo` block if their output is used as a dependency in downstream hooks. This preserves reference equality and ensures subsequent optimizations work as intended.
